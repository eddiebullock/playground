## Part 3. Operating plan for working without the user

**Heartbeat.** A self-paced `/loop` checks the cluster every hour: queue state, result counts, and quota (bytes and file count). The loop prompt points here. Each tick does three things:
1. **Cluster check.** Act on any change: failures are diagnosed and resubmitted, and finished jobs move to the next phase.
2. **Advance the roadmap.** Take the next unblocked step in Part 2, highest phase first.
3. **Keep the record current.** Update STATE.md when anything meaningful changes, and update this file's status column when a step finishes.

**Parallel work.** Delegate independent steps to background agents, at most three at a time, with disjoint files. Each brief states the rules that do not bend, the files it may touch, and "do not commit". The coordinator reviews every diff, runs the tests, checks for stimuli, and then commits and merges. Agents never commit or merge.

**Decision rules when something goes wrong:**
- **Recovery or check fails:** record it with its numbers. Narrow the claim by scope rule, or drop it. Never move a threshold. Log it in DECISIONS.
- **Job fails:** read the log. If the failure is environmental (node, OOM, timeout), resubmit with the same code. If it is a code bug, fix it only if the code is not frozen; frozen code bugs go to DECISIONS as a dated deviation before any rerun.
- **Storage:** stop new writes above 1,080 GB or 1,040,000 files. Clean only this project's own temporary output.
- **SSH failure:** stop cluster work, ask the user to re-authenticate, and keep doing local steps.
- **Mac sleep:** long local runs go under `caffeinate -i` and write per-replicate checkpoints, so they can resume.
- **Ambiguity:** pick the more conservative reading, write it down, and continue. Only items that are truly the user's go to NEEDS_INPUT.

**Merge cadence.** Push p1-pipeline after each coherent step. PR to main with a true merge commit at least once per working block. The PR body has no emojis and ends with the Generated-with line and the session URL.

**Reporting.** A short visible status each tick: what changed, what is next, and anything the user must do. A push notification when a phase completes.
